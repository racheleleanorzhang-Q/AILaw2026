# 文森 AI 管理系统 V2.0 正式基线

## 1. 版本定位

V2.0 以 V1.7 为界面与功能基础，重点统一客户、商机、报价、合同、立项申请、正式项目和跟进任务之间的数据关系。后续开发不得回退到 V1.x 的割裂数据模型。

正式原型：`prototype-v2.0.html`

## 2. 核心对象关系

| 上游对象 | 下游对象 | 关系 | 规则 |
| --- | --- | --- | --- |
| 客户 | 商机 | 1:N | 同一客户可以同时存在多个不同服务需求的商机 |
| 商机 | 报价版本 | 1:N | 报价版本保留在商机详情内；最终确认版本作为合同与立项快照来源 |
| 商机 | 立项申请 | 1:N | 一个综合商机可拆分成多个立项申请和后续项目 |
| 商机 | 合同 | 1:N | 可形成主合同、补充协议或后续合同 |
| 合同 | 项目 | M:N | 框架合同可覆盖多个项目；一个项目也可关联主合同和多份补充协议 |
| 商机 | 跟进任务 | 1:N | 任务记录下一步动作；完成任务时生成不可替代的跟进记录 |

## 3. 客户与商机边界

- 客户状态描述主体准入：潜在客户、准入审批中、正式客户等。
- 商机阶段描述具体合作机会：初步接洽、需求确认、报价沟通、客户确认合作、合同签署中、已转项目、暂停、已关闭。
- 客户状态与商机阶段必须分开存储和展示，不得用客户状态代替商机进度。
- 客户列表不得直接发起立项；正式业务必须先建立商机。
- 准入审批中的客户允许保存商机草稿，但禁止正式报价、发起合同和发起立项。

## 4. 跟进任务与阶段更新

- 跟进任务属于客户/商机阶段，不延伸到正式项目执行阶段。
- 每个任务必须关联唯一商机，同时可通过商机反查客户。
- 完成跟进时记录负责人、方式、客户反馈和可选的下一次跟进时间。
- 完成跟进可以更新商机阶段；阶段变化同时回写商机列表、商机详情和跟进任务页面。
- “合同签署中”和“已转项目”为系统派生阶段，不允许通过普通跟进手工选择。
- 正式项目生成后，任务、工作记录和工时统一进入项目详情管理。

## 5. 合同发起门槛

商机操作中仅在以下条件全部满足时显示“发起合同”：

1. 客户已完成准入并为正式客户；
2. 商机阶段为“客户确认合作”；
3. 已确认最终报价版本；
4. 报价无需审批或已完成审批；
5. 当前商机尚未发起合同。

合同草稿应自动带入客户、商机、服务范围和最终报价快照，避免重复录入。

## 6. 正式项目生成规则

正式项目采用双条件门槛：

- 条件一：至少一项立项申请审批通过；
- 条件二：关联合同已完成签署，或无合同/先开工例外已审批通过。

仅当两个条件同时满足时，系统自动生成正式项目并将对应商机更新为“已转项目”。任一条件未满足时，已通过的立项申请与合同均保留原状态，但不得提前生成项目。

## 7. 跨模块产品形态

- 商机详情展示客户、最终报价、立项申请、合同和项目关系链及双条件状态。
- 合同台账展示来源商机及立项审批状态，并在双签版核验后触发正式项目生成判断。
- 已立项项目的“合同与变更”支持展示一份框架主合同和多份补充协议。
- 项目工作记录、累计工时、任务、文件、结项审批和自动归档继续沿用 V1.7 已确认规则。
- 已归档项目保持只读，不提供新增任务、记录工作和上传文件入口。

## 8. 版本发布原则

- V2.0 为关键版本，应发布正式 HTML 和本基线文档。
- 后续小幅迭代可在本地持续覆盖验证，不要求逐版发布 HTML；只在关键里程碑版本发布 GitHub Pages。
