# AILaw2026 Prototype

面向中国律所业务管理场景的 AI 业务管理系统原型，围绕商机、客户、合同、项目、审批和财务形成完整业务链路。

## 当前正式基线

- 正式版本：V2.5
- 正式原型：[prototype-v2.5.html](./prototype-v2.5.html)
- 在线地址：https://racheleleanorzhang-q.github.io/AILaw2026/prototype-v2.5.html
- 基线说明：[WENSEN_AI_V2.5_BASELINE.md](./WENSEN_AI_V2.5_BASELINE.md)

后续设计和开发必须以 V2.5 为基础，不回退到 V1.x 或 V2.0—V2.4 的旧产品结构。

## 设计原则

- 不做泛 OA，围绕律所业务从商机到项目结项的主链路设计。
- 同一业务对象只保留一个权威数据源，不在不同菜单重复建立台账。
- 列表负责检索、筛选和操作，详情页负责完整信息与关联关系。
- 审批、客户、报价、合同、项目和财务记录必须通过业务对象关联，不允许形成孤立数据。
- 业务状态决定可执行操作，未满足前置条件时不得提前进入后续正式流程。
- 原型采用纯静态 HTML，并通过 GitHub Pages 发布关键版本。

## 已确认的核心业务链路

```text
业务线索与报价
  → 客户确认合作
  → 从商机发起合同
  → 客户准入及利益冲突复核
  → 合同内容、收费及项目安排审批
  → 完成签署并上传双签版
  → AI 核验双签版
  → 系统自动生成正式项目
  → 生成项目应收计划
  → 开票、回款及应收核销
  → 项目结项审批
  → 自动归档并形成项目档案和结项报告
```

## 本轮对话确认的产品结构

### 1. 商机与报价

- 【业务线索】与【报价台账】合并为【商机与报价】，报价台账不再作为独立菜单。
- 商机详情采用【商机信息】【报价明细】【跟进记录】三个 Tab。
- 创建线索允许暂未报价；已明确报价时同步录入首版报价。
- 报价明细保留标准收费、实际报价、折扣率、付款条件、报价方式、审批状态、版本历史和发送记录。
- 客户确认合作、最终报价已确认且报价审批通过后，商机操作中才出现【发起合同】。
- 合同不能脱离客户、商机和最终报价直接创建。

### 2. 客户与利益冲突

- 客户列表和创建商机时的新建客户共用同一个【新增客户】模块。
- 新增客户必须进行利益冲突检查并进入客户准入审批。
- 审批中的客户允许保存商机草稿，但禁止正式报价、合同和项目等后续工作。

### 3. 跟进任务与跟进记录

- 跟进记录是可复用的独立业务模块，在商机详情、跟进任务等入口共享同一份数据。
- 新增跟进记录跟进负责人、下一次跟进时间、跟进备注及客户反馈。
- 跟进任务与商机阶段绑定，可在完成跟进时更新商机阶段。
- 商机进入【客户确认合作】后，才开放合同相关操作。

### 4. 流程审批

- 审批中心下只保留【流程审批】一个菜单。
- 页面分为【待我审批】和【我的申请】两个主 Tab。
- 待我审批第一层状态为【待办】【已办】【抄送】；我的申请第一层状态为【审批中】【已结束】【草稿箱】。
- 第二层按客户准入、报价、项目、合同、财务等审批类型筛选。
- 点击流程后在右侧抽屉展示业务内容、审批节点、审批记录和操作。
- 同意与拒绝均弹出审批意见输入框；拒绝意见必填，同意意见选填。

### 5. 项目管理

- 原【项目承接申请】改为【项目清单】，统一查看立项申请草稿、审批中、已通过、已拒绝和已撤回记录。
- 原【项目台账】改为【已立项管理】，项目执行能力放入项目详情。
- 原【项目归档】改为【已归档项目】。
- 标准合同项目的客户、收费和项目安排随合同一并审批，双签版核验通过后自动生成正式项目；【项目清单】继续承载立项申请、草稿和审批记录。
- 项目详情包括项目概览、执行计划、工作记录、文件与成果、合同与变更、项目动态。
- 工作记录支持记录工作内容和工时，并统计项目总工时。
- 已归档项目为只读状态，不再提供新增任务、记录工作和上传文件操作。
- 项目结项必须满足工作及成果完成、工时核对、文件完整且全部应收款收回。
- 结项由项目负责人发起、办公室主任审批；审批通过后自动归档并生成完整档案和结项报告。

### 6. 合同管理

- 合同台账、合同签署、合同修改/作废和合同归档合并为【合同管理】。
- 合同详情采用只读抽屉，分组展示合同概览、主体与客户、金额与结算、团队与业绩、文件与 AI 核验、审批与操作记录。
- 合同附件统一放入详情页，支持在线查看，不再单独保留【查看文件】操作。
- 合同差异通过【合同状态】或【AI 核验】中的异常状态进入差异详情，不再单独保留【查看差异】操作。
- 合同变更、作废和归档只能从具体合同操作中发起，并进入合同审批流程。
- 【合同管理】不提供全局【发起合同审批】按钮；合同审批只能从符合条件的商机发起。
- 标准合同流程为：商机提交合同 → 客户及利益冲突复核 → 合同内容、收费和项目安排审批 → 签署 → 上传双签版 → AI 核验 → 自动生成项目。

### 7. 应收、开票与回款

- 【付款计划】预留给律所未来的对外付款，不等同于项目应收。
- 【应收计划】用于客户应向律所支付的项目合同款。
- 合同阶段只保存结算条件、开票要求和约定收款方式，不提前生成财务台账。
- 只有双签版核验通过并正式生成项目后，系统才按合同结算条件生成一笔或多笔应收计划。
- 合同开票要求支持【全额开票】【部分/按需开票】【无需开票】。
- 实际回款方式支持银行转账、现金、支票和其他；现金回款必须保存收据及入账凭证。
- 合同管理的【关联台账】按项目状态动态展示：未生成项目时只显示来源商机及提示；生成项目后才显示项目、应收计划、回款记录和开票记录。
- 合同管理中的台账采用只读抽屉；财务管理中的应收计划、回款管理和开票管理查看全部项目及合同数据。
- 开票由项目负责人申请、办公室主任审批、财务开具并上传。
- 回款由财务登记、办公室主任确认，系统自动核销应收并更新项目付款进度。
- 最后一笔回款完成后，系统提醒项目负责人发起结项。

### 8. 数据与经营输出

- 数据中心按客户汇集合同、项目、应收、开票、回款和结项档案。
- 经营中心汇总收入、成本、利润、人员投入、客户满意度、回款周期和项目执行效果。
- 结项数据应为后续报价、人员安排和同类业务管理提供参考。

## 原型重要版本记录

1. V1.0：完成工作台及线索、客户管理的基础设计。
2. V1.1：合并业务线索与报价台账，形成【商机与报价】。
3. V1.4：统一流程审批页面及待办、已办、抄送、我的申请结构。
4. V1.7：完成项目清单、已立项管理、已归档项目及工作记录设计。
5. V2.0：梳理商机、客户、合同、项目和跟进任务的领域关系。
6. V2.1：合并合同台账、签署、变更、作废与归档，形成【合同管理】。
7. V2.2：增加完整合同详情抽屉。
8. V2.3：收敛合同查看、文件、差异和变更/作废操作入口。
9. V2.4：打通项目应收、开票、回款、核销与项目结项审批。
10. V2.5：删除合同管理全局发起入口，项目正式生成后才建立应收、开票和回款台账。

## 下一轮讨论范围

下一轮对话以 V2.5 为基础，重点讨论并设计：

1. 【工时管理】：个人工时、项目工时、工时填报、审核、成本及利用率；
2. 【工作台】：不同角色的待办、提醒、业务进度、风险和经营概览；
3. 【数据中心】：客户、商机、合同、项目、工时、财务和结项数据的汇集方式、指标口径及权限。

在完成上述产品讨论前，不预设具体页面结构和指标口径；确认后再进入下一版本开发。
