# 文森律所运营工作台 V9.1.1 工时管理迭代需求

本文以《WENSEN_AI_V9.1 工时管理迭代需求》为业务基线，并结合 V9.1.1 工时管理产品原型的最终设计，统一说明工时管理的业务目标、状态模型、页面字段、交互规则和验收标准。

本模块计划迭代版本：**V9.1.1**。

产品原型：<https://racheleleanorzhang-q.github.io/AILaw2026/prototype-v9.1.1.html>

本次文档更新原则：

- 不改变 V9.1 已有客户、项目、计费类型、附件和工时校验规则。
- 后端实现不在原型范围内，但文档保留后续实现所需的数据、状态和审批约束。
- 以 V9.1.1 原型中已确认的页面结构和交互为产品验收口径。


## 1. 后端现有能力提取

### 1.1 入口和权限

- 工作台“工时记录”。
- 计时管理“新增计时”。
- 项目详情“计时—新增计时”。
- 普通员工只能登记本人计时。
- 项目成员可以登记本人项目计时。
- 当前后端没有为其他人员代填工时的正式业务流程。

### 1.2 工时类型

| 工时类型 | 客户/项目要求 | 计费工时 |
| --- | --- | --- |
| 律所运营类工作 | 不关联客户和项目 | 不填写 |
| 常法合同计时 | 必须关联客户和项目 | 可以填写 |
| 非常法项目工作 | 必须关联客户和项目 | 不填写 |

### 1.3 字段和校验

- 工作日期不得晚于当天。
- 客户和关联项目。
- 客户对接人。
- 工作类型。
- 工作方式。
- 工作内容。
- 实际用时。
- 完成状态。
- 实际用时按 0.1 小时记录。
- 单条实际用时为 0.1～24 小时。
- 同一员工同一天累计不得超过 24 小时。
- 常法计费工时不得超过实际用时。
- 项目工时最多上传 10 个附件，单个不超过 20 MB。
- 项目工时附件同步进入项目文件与成果及知识中心。
- 律所运营类工作不能上传项目附件。

### 1.4 修改和删除

- 尚未纳入日报的工时可以修改或删除。
- 纳入日报后不能删除。
- 纳入日报后，核心业务字段锁定。
- 纳入日报后只能更新完成状态、完成日期和备注。

### 1.5 今日日报

- 日报汇总当前用户当天全部有效计时。
- 日报同时纳入完成状态为“进行中”和“已完成”的有效工时；完成状态表示工作事项进度，不作为能否提交日报的判断条件。
- 日报按工时记录的“工作日期”归集，不按记录创建时间或工作完成日期归集。
- 系统每天 23:00 自动提交当天符合条件且尚未提交的日报，作为用户忘记手工提交的兜底。
- 当天无计时不能提交。
- 同一天已经提交或批准后不能重复提交。
- 日报包含暂停或不可写项目时不能提交。
- 日报必须存在有效直属上级，不支持无上级自动通过。
- 系统不向普通用户提供通用的历史日报补交入口。
- 未纳入日报的工时不进入正式报表。

### 1.6 报表

当前正式报表只统计直属上级已批准的日报工时：

- 管理统计。
- 客户工时表。
- 按人员统计实际工时、计费工时、项目数和记录数。
- 待审批或被拒绝的日报不进入正式报表。

三个工时报表页签已经通过小版本迭代完成，本次不重复建设页面结构，只调整状态和取数规则。

## 2. V9.1 已补充能力

- 统一工时台账。
- 受控代为填报。
- 分别记录工时记录人和承办律师。
- 代填原因必填。
- 仅当工时记录人与承办律师不同时，工时进入“待确认”。
- 承办律师可在“我的待办”中确认或退回；工时管理页只负责查询和追踪，不重复提供确认入口。
- 待确认代填工时不进入正式统计。
- “记录我的相关工时”可复用公共工作信息创建本人记录。
- 待确认和异常记录集中展示。

## 3. 现状与目标差异

| 差异 | 当前后端 | 目标要求 |
| --- | --- | --- |
| 代填工时 | 只能登记本人 | 授权角色可代填，承办律师确认 |
| 代填确认与日报 | 无代填确认层 | 代填记录先由承办律师确认，再纳入其工作日期对应的日报审批 |
| 已审批工时修改 | 核心字段锁定，无更正流程 | 发起更正审批，生成新版本 |
| 已审批工时删除 | 不允许删除 | 发起撤回审批，保留原记录 |
| 当日漏交 | 23:00 自动提交兜底 | 明确自动提交范围、失败重试和管理员重跑机制 |
| 承办律师调整 | 不支持 | 特殊变更流程，不作为普通编辑 |
| 锁定期 | 只有“纳入日报”锁定 | 增加客户报表、计费、绩效等锁定层级 |
| 项目重开 | 无重开能力 | 重开后新增工时继续关联原项目，并通过重开记录保留时间边界 |

## 4. 工时迭代需求

### TIME-01：统一工时状态模型

优先级：P0。

不再分别设置“登记来源”“本人确认状态”“日报审批状态”和“记录有效性”。工时记录只保留一个统一的“工时状态”字段。

工时状态枚举值：

- 未提交。
- 审批中。
- 待确认。
- 已通过。
- 已退回。
- 已撤回。
- 已锁定。

系统继续保存“工时记录人”和“承办律师”两个事实字段，但不再保存独立的登记来源状态：

| 场景 | 状态流转 |
| --- | --- |
| 工时记录人＝承办律师 | 保存后为“未提交”；提交日报后为“审批中”；审批通过后为“已通过”；驳回后为“已退回”；主动撤回后为“已撤回” |
| 工时记录人≠承办律师 | 保存后为“待确认”；承办律师确认后转为“未提交”，进入承办律师工作日期对应的日报；日报提交后为“审批中”，审批通过后为“已通过”；承办律师退回或日报驳回后为“已退回” |
| 已通过工时进入正式报表、计费、绩效或薪酬结算 | 状态更新为“已锁定” |

其中，“已通过”表示该条工时已经完成其所需的确认或审批，可以进入正式统计；“已锁定”表示该条工时已经被后续正式业务使用，不能直接修改。

“工作状态”与“工时状态”是两个独立字段：

- 工作状态：进行中、已完成，用于描述工作事项完成进度。
- 工时状态：未提交、审批中、待确认、已通过、已退回、已撤回、已锁定，用于描述工时业务流转。
- 工作状态不决定工时能否提交日报；进行中和已完成的有效工时均可纳入日报。

正式报表取数条件：

```text
工时状态为“已通过”或“已锁定”
```

### TIME-02：代填权限和范围

优先级：P0。

| 角色 | 代填范围 |
| --- | --- |
| 项目负责人 | 所负责项目的项目成员 |
| 团队负责人 | 本团队成员 |
| 办公室管理员 | 本办公室人员 |
| 系统管理员 | 授权范围内特殊补录 |

普通员工不能为他人代填。

### TIME-03：代填确认闭环

优先级：P0。

- 仅当工时记录人与承办律师不同时，保存后状态为“待确认”并通知承办律师。
- 承办律师确认或退回。
- 退回原因必填。
- 承办律师确认后，工时状态更新为“未提交”，随后纳入承办律师工作日期对应的日报审批。
- 承办律师退回后，工时状态更新为“已退回”。
- 工时记录人可以撤回待确认记录，状态更新为“已撤回”；修改后再次提交时重新进入“待确认”。
- 状态为“已通过”或“已锁定”后，工时记录人不能直接修改。

### TIME-04：代填工时与日报整合

优先级：P0。

- 工时记录人等于承办律师时，工时通过日报完成审批，状态依次为“未提交—审批中—已通过/已退回/已撤回”。
- 工时记录人不等于承办律师时，先由承办律师确认；确认后状态由“待确认”转为“未提交”，再进入该承办律师的日报审批，不再设置独立的“本人确认状态”。
- 状态为“待确认”“已退回”或“已撤回”的工时不进入正式统计。
- 当天仍有“待确认”的代填记录时不纳入日报，也不阻断其他“未提交”工时提交。
- 日报详情展示工时记录人和承办律师。

### TIME-05：审批中撤回及驳回后重新提交

优先级：P1。

- 日报尚未完成审批时允许申请人撤回，所含工时状态更新为“已撤回”。
- 撤回后关闭原审批任务；再次编辑时工时状态恢复为“未提交”。
- 修改工时后重新提交日报，工时状态更新为“审批中”并生成新审批编号。
- 原审批节点保留历史记录。
- 日报被驳回后，其中的工时状态更新为“已退回”，工时记录恢复为可修改，并向填报人展示驳回原因。
- 填报人修改或删除被指出的工时后，从原工作日期的日报详情点击“重新提交”。
- 重新提交沿用原日报业务编号和工作日期，生成新的日报版本及审批编号；原提交内容、驳回意见和审批过程保留为历史。
- 代填工时被承办律师退回后，由工时记录人修改并重新提交确认，状态重新进入“待确认”。

### TIME-06：已审批工时更正

优先级：P1。

- 操作名称为“申请更正”，不使用普通编辑。
- 展示原值和新值。
- 更正原因必填。
- 原审批人或项目负责人审批。
- 审批期间报表继续使用原版本。
- 更正申请作为独立审批对象记录审批进度，不增加新的工时状态。
- 审批期间原工时继续保持“已通过”或“已锁定”，报表继续使用原版本。
- 通过后新版本生效；原版本进入版本历史，不再使用“已被更正”作为工时状态。

### TIME-07：已审批工时撤回

优先级：P1。

- 已审批记录不能物理删除。
- 需要取消已审批工时时发起撤回申请，申请本身使用独立审批记录，不增加“作废中”状态。
- 审批通过后工时状态更新为“已撤回”，并退出工时报表、客户报表和绩效统计。
- 原记录和审批历史继续可查。

### TIME-08：承办律师变更

优先级：P2。

- 仅项目负责人、工时管理员或系统管理员可发起。
- 记录原、新承办律师及转移原因。
- 通知双方。
- 审批通过后变更当前归属，原工时记录人不变。

### TIME-09：自动提交兜底

优先级：P2。

- 每天 23:00 的自动提交任务按员工和工作日期汇总当日符合条件的有效工时。
- 自动提交只处理状态为“未提交”的工时，包括完成状态为“进行中”和“已完成”的记录；“待确认”“已退回”“已撤回”和“已锁定”不重复提交。
- 自动任务必须幂等：同一员工、同一日期已经存在日报时不得重复创建。
- 自动提交失败时由系统重试并产生运维告警，授权管理员可以重跑该日期的自动提交任务。
- 如果当日 23:00 时没有工时，后续确需补录时填写补录原因和实际工作日期；系统根据工时记录人与承办律师是否相同，分别进入“未提交”或“待确认”。

### TIME-10：项目重开后的工时边界

优先级：P1。

- 项目重开前的历史工时保持只读。
- 项目重开后的新增工时继续关联原项目，不新增用户可见的“服务周期”字段。
- 后端可通过工时创建时间和对应的项目重开申请编号识别其属于重开后新增数据。
- 项目归档、终止或重开审批中不允许新增工时。

### TIME-11：锁定期间

优先级：P2。

当“已通过”工时被用于客户正式报表、计费、开票依据、绩效或薪酬结算时，工时状态更新为“已锁定”。已锁定工时只能走特殊更正，由对应管理角色审批；更正审批期间仍保持“已锁定”。

## 5. V9.1.1 产品设计与交互规格

### 5.1 页面总体结构

- 删除工时管理页面顶部的版本标签、页面标题、副标题和“前端产品原型·模拟数据”等说明区，进入页面后直接展示功能区域。
- 一级页签仅保留“工时台账”和“报表汇总”。
- 删除“今日日报”和“自动提交记录”页签。
- “工时台账”“报表汇总”页签与“提交今日日报”“代为补录工时”“添加计时”操作位于同一行。
- 自动提交仍作为后端兜底能力保留，但不提供独立前台页签。

### 5.2 工时台账筛选区

筛选项在桌面端保持同一基线、等高对齐，避免标签和输入框上下错位。筛选项包括：

| 筛选项 | 规则 |
| --- | --- |
| 工作内容 | 支持关键字搜索 |
| 来源 | 仅保留“全部来源、本人、代填” |
| 工时状态 | 全部状态及七个正式工时状态 |
| 承办律师 | 按承办律师筛选 |
| 完成日期 | 按工作完成日期筛选 |

来源不作为独立业务状态保存，由人员事实字段实时计算：

```text
承办律师＝提报人：本人
承办律师≠提报人：代填
```

“相关工时复用”和“历史导入”不再作为来源筛选枚举；相关工时复用生成的新记录仍按承办律师与提报人的关系归类为“本人”或“代填”。

### 5.3 工时记录表格

表头必须使用单行、单字段单元格，不在同一单元格中拼接两个字段。字段顺序为：

| 字段 | 展示规则 |
| --- | --- |
| 计费类型 | 展示常法合同计时、非常法项目工作或律所运营类工作 |
| 工作类型 | 展示具体工作分类 |
| 工作内容 | 单独展示工作描述 |
| 承办律师 | 展示实际承办律师 |
| 实际用时 | 统一以小时展示 |
| 计费工时 | 不适用时展示“—” |
| 工作状态 | 进行中、已完成 |
| 工时状态 | 七个统一工时状态之一 |
| 附件 | 无附件显示“—”；有附件显示可点击的附件数量 |
| 操作 | 图标和文字操作集合 |

删除“确认 / 日报 / 有效性”和“边界 / 锁定”等复合列，不在台账中展示独立的记录有效性字段。

### 5.4 台账操作规则

| 工时状态/场景 | 编辑操作 | 删除操作 | 说明 |
| --- | --- | --- | --- |
| 未提交 | 直接编辑 | 可删除 | 尚未进入审批和正式统计 |
| 待确认 | 不可编辑 | 不可删除 | 可由提报人撤回后修改；承办律师在“我的待办”确认或退回 |
| 审批中 | “撤回并修改” | 不可删除 | 先关闭原审批任务，再编辑并重新提交，保留原审批轨迹 |
| 已退回 | 直接编辑 | 可删除 | 展示退回原因，修改后重新提交 |
| 已撤回 | 直接编辑 | 可删除 | 修改后重新提交 |
| 已通过 | “申请更正” | 不可物理删除 | 原版本在审批期间继续用于报表 |
| 已锁定 | “申请特殊更正” | 不可物理删除 | 由对应管理角色审批 |
| 项目重开前历史工时 | 只读 | 不可删除 | 不因项目重开而解除历史锁定 |

操作列不使用通用“查看详情”替代编辑和删除：

- 默认展示编辑和删除图标，并根据状态启用或置灰。
- 当记录的承办律师不是当前用户时，补充“记录我的相关工时”。该操作复用客户、项目、工作内容等公共信息，创建当前用户本人的独立工时记录。
- 查看详情仅用于“待确认与异常”记录追踪，不作为工时台账的主操作。

### 5.5 附件查看与下载

- 附件列展示附件数量，例如“1 个”“2 个”。
- 点击附件数量后打开附件列表，展示每个文件的完整文件名。
- 每个附件提供独立下载操作。
- 无附件时展示“—”，不提供点击交互。
- 附件上传数量、大小和项目资料同步规则继续沿用 V9.1 校验。

### 5.6 添加计时与代为补录工时

- “添加计时”必须完整复用 V9.1 的“添加计时”弹窗，不得改为简化表单。
- “代为补录工时”必须完整复用 V9.1 的“代为补录工时”弹窗，不得删减原字段、联动和校验。
- 两个弹窗继续包含基础信息、业务关联、工作记录、完成信息、实际与计费工时、备注和附件等原有内容。
- 代为补录在原表单基础上增加受控代录提示、承办律师选择和必填的代填原因，并执行 TIME-02 的权限范围。
- 按钮命名统一为“添加计时”和“代为补录工时”，不使用“登记工时”“代计工时”等新名称。

### 5.7 提交今日日报

- 不再设置“今日日报”独立页签，工时台账顶部提供“提交今日日报”按钮。
- 点击后弹窗展示可纳入记录数、实际用时合计、计费工时合计和本次提交明细。
- 提交范围按当前用户、工作日期和当前有效工时计算，不受台账筛选条件影响。
- 状态为“待确认”的代填记录不进入本次日报，但不阻断其他“未提交”工时提交。
- 当待确认记录存在时，弹窗明确提示数量和处理规则。
- 提交后固化工时版本集合，生成日报版本和审批编号，相关工时状态更新为“审批中”。
- 没有可提交记录时，确认提交按钮不可用。

### 5.8 报表汇总

报表汇总保留以下页签：

- 管理统计。
- 客户工时表。
- 待确认与异常。

“待确认与异常”列表使用单行字段，字段顺序为：工作日期、工作内容、承办律师、提报人、时长、代录原因、状态、操作。

该列表用于查询和追踪以下记录：

- 代为补录后仍待承办律师确认的记录。
- 被承办律师退回的记录。
- 日报审批被驳回的记录。
- 已提交普通更正、撤回或承办律师变更审批的记录，状态统一展示为“审批中”，不创造“作废审批中”等新工时状态。
- 已锁定且正在申请特殊更正，或特殊更正已经完成、需要保留追踪记录的工时。

以下记录不进入该列表：

- 没有异常或变更流程的普通“已锁定”工时。
- 仅处于正常“已通过”状态的工时。
- 需要承办律师实际办理确认或退回的待办操作；该操作统一在承办律师的“我的待办”处理。

操作列仅提供“查看详情”。详情中展示人员、业务信息、原因和流转轨迹，删除“记录有效性：当前有效”字段。

### 5.9 状态展示约束

- 页面不得展示“作废审批中”作为工时状态；作废/撤回申请在审批期间统一展示“审批中”。
- 普通已锁定工时只在台账中展示，不因已锁定自动进入“待确认与异常”。
- 更正、撤回、承办律师变更和特殊更正使用独立审批对象记录原因、原值、新值及审批轨迹，不扩充七个工时状态枚举。
- 页面可在详情中展示确认、日报和变更轨迹，但这些信息不是独立的台账状态列。

## 6. 工时底层逻辑

1. 工时更正生成新版本，不覆盖原记录。
2. 工时记录保存工时记录人、承办律师和实际确认人；不再保存独立的登记来源状态。
3. 承办律师确认和日报审批共用一个“工时状态”字段。系统根据工时记录人与承办律师是否相同决定初始进入“待确认”还是“未提交”；代填确认后由“待确认”转为“未提交”，再进入日报审批。
4. 日报保存提交时的工时版本集合，避免后续修改改变原审批内容。
5. 更正通过后，系统更新正式报表使用的当前版本，但保留原日报审批快照和历史版本。
6. 已审批工时撤回后状态为“已撤回”，不删除附件、审批和审计记录。
7. 同一天 24 小时校验按承办律师计算，而不是按工时记录人计算。
8. 计费工时限制继续沿用现有计费类型规则。

## 7. 验收标准

### 7.1 页面与字段

- 工时管理页不再展示顶部版本说明区。
- 一级页签只有“工时台账”和“报表汇总”，不存在“今日日报”和“自动提交记录”页签。
- 三个主操作与页签处于同一行，筛选项在桌面端对齐。
- 工时台账字段、顺序和单行展示符合 5.3，且包含“承办律师”。
- 来源筛选只有“全部来源、本人、代填”，计算结果符合人员关系。

### 7.2 核心交互

- “添加计时”和“代为补录工时”打开 V9.1 完整表单，字段和联动不被简化。
- 审批中工时可通过“撤回并修改”进入编辑；已通过工时通过“申请更正”修改；已锁定工时通过“申请特殊更正”修改。
- 操作列正确显示编辑、删除和“记录我的相关工时”，并按状态控制可用性。
- 点击附件数量可看到文件名并完成单文件下载。
- “提交今日日报”能够展示正确范围和汇总，台账筛选不影响提交范围。

### 7.3 状态与异常

- 页面只使用七个正式工时状态，不出现“作废审批中”等额外状态。
- 待确认代填工时由承办律师在“我的待办”处理，报表页不重复提供确认和退回按钮。
- 正常已锁定记录不进入“待确认与异常”；仅特殊更正相关的已锁定记录进入追踪列表。
- “待确认与异常”详情不显示“记录有效性：当前有效”。
- 正式报表只统计“已通过”或“已锁定”工时。
