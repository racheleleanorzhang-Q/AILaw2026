# WENSEN AI V9.2.4 财务管理优化页面及功能设计

> 本文以 V9.2.4 原型为当前实现基线，覆盖结算期次、开票申请、登记发票、回款/退款登记及核销明细。本文件同时标明当前原型尚未完整呈现的联动能力，避免将后续设计误写为已实现功能。

## 一、优化范围

本次优化涉及：

1. 结算期次。
2. 开票申请及审批。
3. 登记发票。
4. 开票记录。
5. 登记回款及退款。
6. 回款记录。
7. 核销明细。
8. 项目、合同关联财务台账。
9. 财务顶部指标。

不改变现有财务关系：

- 一个结算期次可以对应多次开票申请及多张发票。
- 一张发票可以对应多笔回款。
- 一笔回款可以核销多张发票。
- 发票与回款继续保持多对多关系。
- 蓝票继续使用现有申请、审批及登记发票流程。
- 回款继续使用现有登记回款及核销流程。

不新增独立的：

- 红票审批页面。
- 红票登记页面。
- 退款页面。
- 退款审批流程。
- 退款核销页面。

## 二、核心业务逻辑

### 2.1 原合同金额不直接修改

合同进入执行并产生开票后：

- 原合同金额不允许直接修改。
- 原合同税前金额、税率和税后金额保持不变。
- 原合同生成的结算期次不修改。
- 通过新增“金额调增”或“金额调减”期次调整整体合同金额。
- V9.2.4 不在结算期次弹窗中新增补充合同上传字段。
- 调整依据仍可通过现有合同附件管理保存；新增金额调增、金额调减期次时必须填写调整原因。

### 2.2 整体合同金额

```text
整体合同金额
= 原合同金额
+ 金额调增期次
- 金额调减期次
```

例如：

```text
原合同金额 100,000
+ 金额调增 0
- 金额调减 20,000
= 整体合同金额 80,000
```

### 2.3 净开票金额

```text
净开票金额
= 蓝票金额－红票金额
```

### 2.4 净回款金额

```text
净回款金额
= 实际回款金额－退款金额
```

### 2.5 多收款余额

```text
多收款余额
= MAX（0，净回款金额－整体合同金额）
```

以上金额必须使用相同币种及相同含税口径计算。

### 2.6 金额调减后的待处理金额

金额调减期次只负责调整整体合同金额，不代表必然需要红冲或退款。系统应分别计算：

```text
应红冲金额
= MAX（0，当前净开票金额－调整后整体合同金额）

应退款金额
= MAX（0，当前净回款金额－调整后整体合同金额）
```

- 是否需要红票，由净开票金额是否超过调整后整体合同金额决定。
- 是否存在多收款，由净回款金额是否超过调整后整体合同金额决定。
- 应红冲金额、应退款金额与金额调减期次金额可以不同。
- 如果应红冲金额和应退款金额均为0，金额调减期次登记后即可完成。
- V9.2.4 的退款登记必须关联至少一张已登记红票，不支持无红票直接登记退款。

## 三、结算期次

### 3.1 结算期次列表

#### 页面调整

现有字段、顺序和展示逻辑保持不变，只增加一个字段：

**期次类型**

调整后的字段为：

| 合同与项目 | 结算期次 | 期次类型 | 付款条件 | 预计付款日期 | 税前金额 | 合同金额税前 USD | 税率 | 预计税后金额 | 已开票 | 状态 |
|---|---|---|---|---|---|---|---|---|---|---|

#### 期次类型

- 原合同期次。
- 金额调增。
- 金额调减。

#### 金额展示

- 原合同期次按原金额展示。
- 金额调增按正数展示。
- 金额调减按负数展示。
- 其他字段保持不变。
  

### 3.2 添加结算期次弹窗

#### 新增字段

在现有弹窗中增加：

**期次类型**

选项：

- 金额调增。
- 金额调减。

#### 现有字段保持不变

继续保留：

- 所属项目。
- 关联合同。
- 期次。
- 预计付款日期。
- 税前金额。
- 税率。
- 预计税后金额。
- 付款条件。

可以增加：

- 调整原因。

#### 金额调增

- 用户录入正数。
- 系统按正数保存和展示。
- 金额计入整体合同金额。

#### 金额调减

- 用户仍录入正数。
- 系统按负数保存、计算和展示。
- 金额从整体合同金额中扣减。

#### 校验规则

- 用户不能直接录入负数。
- 金额调减后整体合同金额不得小于0。
- 币种沿用关联合同币种。
- 已产生后续开票、回款数据的调整期次不得直接删除。
- 如需更正，应新增反向调整期次。

### 3.3 结算期次状态

结算期次根据金额方向使用不同状态体系。

#### 正向期次

适用于：

- 原合同期次。
- 金额调增期次。

状态包括：

- 未开票。
- 部分开票。
- 已开票。
- 部分回款。
- 已结清。

基本流转：

```text
未开票
→ 部分开票
→ 已开票
→ 部分回款
→ 已结清
```

根据实际业务可以跳过中间状态。

逾期提示，可单独显示日期预警。

#### 负向期次

适用于：

- 金额调减期次。

状态包括：

- 待红冲。
- 部分红冲。
- 已红冲。
- 待退款。
- 已完成。

负向期次不是固定的线性流转。系统在金额调减期次生效后，分别计算应红冲金额和应退款金额，再确定处理路径。

#### 路径一：既不需要红冲，也不需要退款

```text
金额调减期次登记 → 已完成
```

适用条件：

```text
净开票金额 ≤ 调整后整体合同金额
并且
净回款金额 ≤ 调整后整体合同金额
```

例如：原合同金额10万元，调减2万元，调整后整体合同金额8万元；当前净开票未超过8万元，实际只回款8万元。此时只登记一笔金额调减2万元的期次，不需要红票，也不需要退款，期次直接进入“已完成”。

#### 路径二：需要红冲和退款

```text
待红冲 → 部分红冲 → 已红冲 → 待退款 → 已完成
```

适用条件：净开票金额和净回款金额均超过调整后整体合同金额。完成红票登记后，退款可关联一张或多张已登记红票；完成全部应退款金额后进入“已完成”。

#### 路径三：仅需要红冲

```text
待红冲 → 部分红冲 → 已红冲 → 已完成
```

适用条件：净开票金额超过调整后整体合同金额，但净回款金额未超过调整后整体合同金额。

#### 不支持的路径：无红票直接退款

V9.2.4 不允许在没有已登记红票的情况下直接登记退款。即使净回款金额超过调整后整体合同金额，退款登记仍需先具备可关联、且存在可退款余额的红票。

状态由系统根据应红冲金额、应退款金额及其实际完成情况自动计算，不允许手工选择或手工跳转。

> 当前原型的自动状态计算重点呈现“待红冲、待退款、已完成”。“部分红冲、已红冲”已保留在完整业务状态设计中，后续需按累计红票金额进一步细化页面呈现。

## 四、开票申请

### 4.1 开票申请弹窗

#### 新增字段

在现有开票申请中增加：

**发票性质**

选项：

- 蓝票，默认。
- 红票。

### 4.2 蓝票申请

选择蓝票时，只增加“发票性质”字段，其他逻辑全部保持现状，包括：

- 项目、合同和结算期次联动。
- 结算期次选择范围。
- 金额填写及校验规则。
- 币种、税率和购方信息带出。
- 一个结算期次多次开票。
- 现有审批流程。
- 审批通过后的登记发票流程。

不新增蓝票限制，不调整现有可开票金额计算规则。

### 4.3 红票申请

选择红票时显示：

- 关联结算期次，非必填。
- 原蓝票，必填。
- 原蓝票号码。
- 原蓝票金额。
- 已红冲金额。
- 可红冲金额。
- 本次红冲金额。
- 红冲原因。

#### 关联结算期次规则

- 可选择当前项目、合同下的任一结算期次。
- 不限定为金额调减期次。
- 可以不关联结算期次。
- 未选择时不自动回填第一期。
- 原蓝票是红票的核心必选关联，结算期次仅用于辅助归属。

#### 红票校验

单张原蓝票：

```text
可红冲金额
= 原蓝票金额－已生效红票金额
```

整体预计需红冲金额：

```text
预计需红冲金额
= MAX（0，累计蓝票金额－整体合同金额）
```

实际红票金额不要求等于金额调减期次金额。

例如原合同10万元，调减2万元，整体合同金额8万元：

| 累计蓝票 | 预计需红冲 |
|---:|---:|
| 80,000 | 0 |
| 90,000 | 10,000 |
| 100,000 | 20,000 |

### 4.4 开票申请审批及详情

继续复用现有开票申请审批流程。

蓝票：

- 继续执行现有审批逻辑。
- 不增加新的审批节点或规则。

红票：

- 使用相同审批节点和审批操作。
- 展示发票性质。
- 展示关联结算期次；未关联时展示“—”。
- 展示原蓝票信息。
- 展示本次红冲金额及原因。
- 审批通过后进入现有登记发票流程。
- 审批拒绝后不计入红票金额。

不新增红票审批页面。

## 五、登记发票及开票记录

### 5.1 登记发票弹窗

原设计中的“发票上传”对应现有“登记发票”弹窗。

继续使用现有流程：

```text
选择已通过的开票申请
→ 上传发票进行票面识别，或手工填写
→ 自动带出项目、合同及申请已关联的结算期次；红票期次可以为空
→ 核对发票信息
→ 保存发票
```

#### 蓝票登记

选择蓝票开票申请时：

- 完全沿用现有登记发票逻辑。
- 现有字段保持不变。
- 票面识别保持不变。
- 手工登记方式保持不变。
- 保存方式保持不变。

#### 红票登记

选择红票开票申请时：

- 自动识别发票性质为红票。
- 带出申请中选择的结算期次；申请未关联期次时保持为空。
- 自动带出原蓝票。
- 自动带出红冲金额和税率。
- 上传实际红字发票或手工登记。
- 用户填写及票面识别金额仍使用正数。
- 系统汇总时按负数处理。
- 保存时允许结算期次为空；为空时不生成虚假的期次分摊记录。

不新增独立的红票登记页面。

### 5.2 开票记录

继续使用现有开票记录区域。

调整内容：

- 支持展示蓝票和红票。
- 红票按负向金额参与统计。
- 红票必须关联原蓝票。
- 红票可关联当前项目、合同下的任一期次，也可以不关联期次。
- 净开票金额按蓝票减红票计算。

列表尽量复用现有字段：

- 在“发票号码/日期”区域增加蓝票或红票标识。
- 红票可在原有发票信息中展示原蓝票号码。
- 其他字段保持不变。
- 不新增独立红票列表。

## 六、登记回款及退款

### 6.1 回款记录

继续使用现有回款记录页面，不新增退款列表。

V9.2.4 继续使用同一回款记录页面，并为回款、退款统一展示以下字段：

- 所属合同与项目。
- 记录类型。
- 记录日期。
- 付款/收款方。
- 银行流水号。
- 实际金额。
- 折算 USD。
- 附件。
- 分配状态。

#### 退款展示

- 退款保存后仍展示在回款记录中。
- 退款金额在“实际金额”字段中按负数展示，并使用明显的退款标识。
- 记录日期对应退款日期。
- 付款/收款方位置展示退款收款方。
- 银行流水号展示退款流水。
- 附件展示退款凭证。
- 不新增独立退款字段或退款列表。

### 6.2 登记回款弹窗

登记退款复用现有“登记回款”弹窗，不新增登记退款页面。

#### 新增字段

增加：

**记录类型**

选项：

- 回款，默认。
- 退款。

#### 选择回款

完全沿用现有登记回款逻辑：

- 所属项目及合同。
- 到账日期。
- 付款方。
- 银行流水号。
- 实际回款币种及金额。
- 发票核销分配。
- 回款附件。
- 保存回款与核销。

#### 选择退款

在同一页面中进行适配：

- 到账日期对应退款日期。
- 付款方对应退款收款方。
- 实际回款金额对应实际退款金额。
- 银行流水号记录退款流水。
- 回款附件用于上传退款凭证。
- 用户输入正数，系统按负向资金记录计算。

原“核销发票分配”区域适配为：

- 关联已登记红票，必填。
- 本次核销金额。
- 一笔退款可以增加多条核销行，关联多张红票。
- 结算期次不单独选择，读取红票关联的结算期次；红票未关联期次时为空。

#### 退款校验

- 退款必须至少关联一张当前项目、合同下已登记的红票。
- 退款不能关联蓝票。
- 本次退款核销金额合计必须等于实际退款金额。
- 单张红票累计退款金额不得超过该红票可退款金额。
- 一笔退款可以关联多张红票。
- 一次实际银行支付只形成一条退款业务记录。
- 分多次退款时，按实际支付次数形成多条退款记录。
- 退款完成后不修改原始回款金额。
- 当前原型未增加“原回款”选择字段，也未实现合同级多收款余额的二次校验；当前校验以红票可退款余额为准。

## 七、核销明细

继续使用现有核销明细页面。

现有字段全部保持不变：

- 合同与项目。
- 记录类型。
- 回款。
- 发票。
- 结算期次。
- 核销/调整金额。
- 操作人/时间。
- 状态。

“记录类型”完整支持：

- 回款核销。
- 退款。
- 汇兑调整核销。

退款记录示例：

| 记录类型 | 回款 | 发票 | 结算期次 | 核销/调整金额 | 状态 |
|---|---|---|---|---:|---|
| 退款 | REF-退款记录编号 | 关联红票 | 红票关联期次或— | -10,000 | 有效 |

登记退款时只生成一条退款业务记录。

同一条退款记录可以在：

- 回款记录中作为负向资金记录展示。
- 核销明细中作为“退款”类型展示。

两处使用同一数据源，不是重复生成两条记录。

不再额外生成：

- 核销冲回记录。
- 退款核销记录。
- 第二条负向回款记录。

有效净核销金额由系统计算，不单独形成业务记录。

## 八、顶部财务指标

不新增指标卡，只调整现有计算口径。

### 8.1 合同税前总额

```text
合同税前总额
= 原合同税前金额
+ 金额调增税前金额
- 金额调减税前金额
```

### 8.2 预计税后总额

按原合同期次、金额调增期次和金额调减期次计算。

### 8.3 已开票金额

```text
已开票金额
= 蓝票金额－红票金额
```

### 8.4 已回款金额

```text
已回款金额
= 实际回款金额－退款金额
```

现有进度比例继续使用调整后的预计税后总额作为分母。

## 九、关联页面同步

### 9.1 项目详情－财务台账

项目详情继续与一级财务管理使用同一数据源。V9.2.4 的底层数据已支持：

- 结算期次类型。
- 金额调增和金额调减。
- 正向期次和负向期次状态。
- 蓝票和红票。
- 回款和退款。
- 核销明细中的退款类型。

不建立另一套计算或操作逻辑。

> 当前 V9.2.4 主要完成一级财务管理页面；项目详情财务台账尚未完整同步全部新表头、类型标识和操作入口。

### 9.2 合同详情－关联财务台账

合同详情继续复用财务管理数据，计算时使用调整后的结算期次、净开票和净回款口径。

目标展示内容包括：

- 原合同金额。
- 金额调增、金额调减期次。

## 十、典型场景验收

### 10.1 累计蓝票9万元、实际回款9万元

| 项目 | 金额 |
|---|---:|
| 原合同金额 | 100,000 |
| 金额调减期次 | -20,000 |
| 整体合同金额 | 80,000 |
| 蓝票累计 | 90,000 |
| 红票 | -10,000 |
| 净开票 | 80,000 |
| 实际回款 | 90,000 |
| 退款 | -10,000 |
| 净回款 | 80,000 |

### 10.2 累计蓝票10万元、实际回款9万元

| 项目 | 金额 |
|---|---:|
| 原合同金额 | 100,000 |
| 金额调减期次 | -20,000 |
| 整体合同金额 | 80,000 |
| 蓝票累计 | 100,000 |
| 红票 | -20,000 |
| 净开票 | 80,000 |
| 实际回款 | 90,000 |
| 退款 | -10,000 |
| 净回款 | 80,000 |

### 10.3 净开票未超过8万元、实际回款8万元

| 项目 | 金额 |
|---|---:|
| 原合同金额 | 100,000 |
| 金额调减期次 | -20,000 |
| 整体合同金额 | 80,000 |
| 净开票 | ≤80,000 |
| 实际回款 | 80,000 |
| 应红冲金额 | 0 |
| 应退款金额 | 0 |

处理结果：只登记一笔金额调减2万元的结算期次，不发起红票申请，不登记退款，金额调减期次直接进入“已完成”。

结论：

- 三种情况下金额调减期次均为-20,000元。
- 红票可能为-10,000元或-20,000元。
- 当净开票未超过调整后的整体合同金额时，应红冲金额为0。
- 当净回款未超过调整后的整体合同金额时，应退款金额为0。
- 红票金额与退款金额不要求相等。

## 十一、明确不调整的内容

- 不修改现有一期多票关系。
- 不修改发票与回款多对多核销关系。
- 不修改蓝票申请逻辑。
- 不新增红票审批流程。
- 不新增独立红票登记页面。
- 不新增独立退款页面。
- 不新增退款审批流程。
- 结算期次列表除“期次类型”外，不增加其他字段。
- 开票记录尽量复用现有字段。
- 回款记录不新增独立退款列表，但增加“记录类型”，并将日期、往来方和金额列改为回款/退款通用名称。
- 核销明细除新增“退款”记录类型外，不修改其他字段。
