# 文森律所运营工作台 V9.1 合同管理迭代需求

本文从《WENSEN_AI_V9.1 后端现状对照与三模块迭代需求》中拆分，聚焦合同管理现状、合同变更、项目重开联动和底层逻辑。


## 1. 后端现有能力提取

### 1.1 使用前提和权限

- 项目已完成立项审批并处于可履约状态。
- 当前用户是项目有效成员。
- 项目负责人的 HR 任职和直属上级有效。
- 项目成员可以新增合同。

### 1.2 合同字段

- 合同名称。
- 服务类型。
- 签约日期和可选到期日期。
- 服务内容简介和备注。
- 合同源文件可选，也可以完全手填。
- 客户签约主体固定继承项目主客户，不允许在合同中更换。
- 我方签约主体及比例。
- 案件来源人或团队及案源提成。
- 服务团队、负责人和分配比例。
- 币种、计费方式、付款方式和分期方式。
- 结算明细。

### 1.3 计费与结算

支持：

- 小时计费，无封顶价。
- 小时计费，有封顶价。
- 固定总价。
- 固定基础费用加风险费用。

除无封顶小时计费外，结算明细税前总额必须等于合同计费金额。无封顶小时计费审批通过时不生成期次，可由项目成员在实际账单确认后手工添加。

### 1.4 合同审批

- 审批人取项目负责人的直属上级，而不是合同录入人的直属上级。
- 有有效上级时进入“审批中”。
- HR 明确无直属上级时可按规则自动通过。
- 任职、上级快照或账号缺失时不能保存为已通过。
- 退回后审批状态标记为退回，合同状态沿用“待上传”，项目成员可修改并重新提交。
- 审批通过后变为“已批准”，并按付款计划生成结算期次。

### 1.5 当前缺失

- 审批中合同撤回删除。
- 审批中合同重新上传。
- 已审批合同重新上传。
- 已审批合同内容变更。
- 合同作废及项目终止、归档后的合同只读控制。
- 合同版本及生效日期。
- 项目重开后的合同复用或补充协议机制。

## 2. 现状与目标差异

| 差异 | 当前后端 | 目标要求 |
| --- | --- | --- |
| 审批中删除 | 无 | 撤回审批并逻辑删除 |
| 审批中重传 | 无 | 保留编号，替换文件后重新审批 |
| 补充材料 | 退回后修改 | 不改正文时可补充材料，不重启审批 |
| 已审批文件错误 | 无重新上传机制 | 重新上传审批，合同页展示最新文件，原文件保留审计 |
| 已审批内容变化 | 不支持 | 生成新合同版本和变更审批 |
| 作废 | 不支持 | 无下游财务时可申请作废 |
| 项目终止/归档 | 无统一合同权限控制 | 合同随项目只读，不设独立合同终止 |
| 项目重开 | 无 | 判断原合同有效性、范围和剩余额度 |
| 财务联动 | 审批通过一次性生成期次 | 只调整未来未使用期次，历史财务锁定 |

## 3. 合同迭代需求

### CONTRACT-01：合同状态统一

优先级：P0。

产品侧合同状态沿用：

- 待上传。
- 已通过。

审批中、退回、拒绝、合同修改审批中和重新上传审批中属于审批状态，不新增“待修改”或“变更审批中”合同状态。退回后合同状态沿用“待上传”；已通过合同发起修改或重新上传时，审批期间合同状态仍为“已通过”。项目终止或归档后合同随项目只读，不设置独立“已终止”合同状态。

### CONTRACT-02：审批中撤回并删除

优先级：P0。

- 上传人或项目负责人可操作。
- 原审批标记申请人撤回。
- 合同退出普通台账。
- 后端保留合同编号、文件、审批及删除日志。
- 如果已经产生任何结算期次或其他下游数据，不允许走此操作。

### CONTRACT-03：审批中重新上传

优先级：P0。

- 保持合同编号。
- 原文件标记“已替换”。
- 原审批流程关闭。
- 填写重新上传原因。
- 新文件重新提交审批并生成新审批编号。
- 审批人可以对比新旧文件。

### CONTRACT-04：审批中补充材料

优先级：P1。

- 不替换合同正文。
- 不重启审批。
- 记录补充人、时间和附件分类。
- 通知当前审批人。

### CONTRACT-05：已审批合同重新上传

优先级：P1。

适用于错传、漏页或扫描不清，且合同内容没有变化：

- 重新上传正确文件。
- 重新上传原因必填。
- 原合同审批人确认。
- 新文件成为当前展示版本。
- 合同页只展示最新文件；原文件和替换记录在后台审计及“审批与动态”中保留。
- 合同金额和结算期次不变。

### CONTRACT-06：已审批合同内容变更

优先级：P0。

适用于主体、范围、期限、金额、税率、付款方式、收款账户、结算计划或团队分配变化：

- 创建合同新版本。
- 保存原值和新值。
- 上传补充协议或其他变更依据。
- 原版本在审批期间继续有效。
- 审批通过后按生效日期切换当前有效版本。

### CONTRACT-07：合同作废

优先级：P1。

- 无结算期次、开票、回款和核销时可以申请作废。
- 只有未使用结算期次时，可在作废审批通过后同步取消。
- 已产生开票、回款或核销时不允许作废。
- 作废后合同编号和记录继续保留。

### CONTRACT-08：项目终止或归档后的合同控制

优先级：P1。

- 不设置独立合同终止操作、审批流程或“已终止”合同状态。
- 项目终止或归档后，合同随项目状态只读。
- 已发生应收、开票、回款和核销继续按照项目终止或归档规则处理。
- 撤销终止或撤销归档通过后，合同操作权限随项目权限恢复。

### CONTRACT-09：合同与项目重开

优先级：P0。

- 原合同仍有效且覆盖新工作时，重开项目继续使用原合同。
- 不复制合同和结算期次。
- 原合同到期、终止、作废或范围不覆盖时，项目统一进入“待合同”。
- 如果只需要补充协议，在合同处理信息中标记“需补充协议”，不增加项目状态。
- 新合同或合同变更可记录来源重开申请编号，用于后台审计；项目端通过阶段序号展示所属项目历程，不新增独立服务周期关联页面。

### CONTRACT-10：合同额度延续

优先级：P0。

- 有封顶小时合同重开后继续使用原剩余额度。
- 不因项目重开重置封顶价或已使用金额。
- 无封顶小时合同按实际账单或批准期次累计。
- 固定基础费用与预计风险费用分开计算。

### 3.11 本期不覆盖的合同客户主体能力

以下能力暂不纳入本期：

- 多个客户签约主体。
- 同一客户更名后的合同展示和处理。
- 合同主体承继。
- 因主体承继产生的应收转移。

本期合同客户签约主体继续固定继承项目主客户。

### CONTRACT-11：结算期次调整

优先级：P0。

- 未开票、未回款的未来期次可以调整或取消。
- 开票审批中的期次必须先处理审批。
- 已开票、已回款、已核销期次不可覆盖。
- 调减后的合同金额不得低于已开票金额或已确认收入。
- 调增只生成增量期次，不复制原期次。

## 4. 合同底层逻辑

1. 合同主记录保存合同身份，合同版本保存正文和商业条款。
2. 同一时间只有一个当前有效合同版本。
3. 合同审批通过时生成版本对应的结算计划和应收期次。
4. 后续变更只对未来未使用期次产生增量、替换或取消记录。
5. 已发生的开票、回款和核销始终关联发生时的合同版本与期次快照。
6. 重新上传和内容修改使用不同流程；重新上传不得改变结构化合同字段。
7. 合同作废表示登记不应继续作为有效依据；项目提前结束履行通过项目终止或归档控制，不设置独立合同终止。
8. 本期合同客户主体继续继承项目主客户，不增加多主体和主体承继逻辑。

---

## 5. 合同与项目重开、财务联动

1. 项目重开不自动复制或恢复合同和结算期次。
2. 原合同有效且覆盖新增工作范围时，继续使用原合同及剩余额度；封顶额度和已使用金额不重置。
3. 原合同范围不覆盖时，通过补充协议或合同内容变更生成新版本；原合同到期、终止或作废时应签订新合同。
4. 合同内容变更只调整未来未使用的结算期次；已开票、已回款和已核销记录保持发生时的合同版本及金额快照。
5. 合同调增只生成增量期次；合同调减后的金额不得低于已开票金额或已确认收入。
6. 新合同、补充协议或合同变更记录来源重开申请编号，作为重开后新增应收和开票的依据。
